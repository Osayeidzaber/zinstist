## LiquidBounce

The first-person swing transforms in `SwingAnimationsModule` are adapted from `SwingAnimations.kt`; the injection point is adapted from `MixinFirstPersonHandsAndItems.java`. Both originate from LiquidBounce, Copyright (c) 2015-2026 CCBlueX, licensed under GPL-3.0-or-later. Source snapshot: https://github.com/CCBlueX/LiquidBounce/tree/e033f5aaf05be802dd2ca51782f255119d7d5654. The Kotlin module/value/event framework was not copied; the animation math and mode behavior were translated to Java and integrated with Jilaton's own settings, config, UI, and module lifecycle.

`VelocityModule` adapts LiquidBounce's local-player velocity scaling behavior from `ModuleVelocity` / `VelocityModify` at the same source snapshot. Jilaton's packet mixin and settings integration are Java implementations in Jilaton's module lifecycle.

`AntiBotModule` adapts the `NotInTabList` target-filter behavior from LiquidBounce's `ModuleAntiBot` at the same GPL-3.0-or-later source snapshot. The filter is shared by KillAura, AimAssist, and Triggerbot through Jilaton's `PlayerTargetFilters` helper.

`NoSlowModule` and `NoSlowMixin` adapt LiquidBounce's item-use input-multiplier and sprint-while-using hooks from `ModuleNoSlow` / `MixinLocalPlayer`, under GPL-3.0-or-later at the source snapshot above.

`AimAssistModule` adapts target persistence and range/FOV hysteresis from the supplied Anubis 0.9.9.3 `AimAssistModule` decompilation, with the user's stated permission to reuse that code. The supplied reference snapshot is CFR output from JAR SHA-256 `c5259f9ffee4bbe2511972f7941ab6fc2dcda691dc0d5ab18a558f3f8f4285de`.

`CrystalAuraModule` and `CrystalDamageEstimator` adapt the target selection, crystal-base eligibility, conservative self-damage guard, explosion falloff, armor reduction, and exposure sampling approach from the supplied Anubis 0.9.9.3 `CrystalAuraModule`, `Crystals`, and `CrystalDamage` decompilation. The user stated they have permission for this reuse. The implementation is integrated into Jilaton's Java module/settings/config system and is not a wholesale copy. Reference JAR SHA-256: `c5259f9ffee4bbe2511972f7941ab6fc2dcda691dc0d5ab18a558f3f8f4285de`.

`AutoAnchorModule` adapts the explicit right-click, place/charge/detonate lifecycle and conservative lethal-blast check from Anubis's `SingleAnchorMacroModule`. Jilaton uses its own Fabric callback, hotbar state machine, configurable self-damage ceiling, friend-protection check, and `CrystalDamageEstimator` configured for respawn-anchor power 5.0. Anubis's block-shield planner and Double mode are not included. Anubis is GPL-3.0; supplied JAR SHA-256: `c5259f9ffee4bbe2511972f7941ab6fc2dcda691dc0d5ab18a558f3f8f4285de`.

`AnchorAuraModule` adapts Anubis's `AnchorAuraModule` scoring and place/charge/detonate planning into Jilaton's Java module lifecycle. Its target ranking follows the observed `Combo.value` policy (ordinary damage, totem pop, then lethal), and candidate pruning uses a damage upper bound. Jilaton retains its own friend/self safety checks, visible turn smoothing, and inventory ownership/restore logic; Anubis's server-rotation abstraction, RTT/hurt prediction, shielding planner, and render/HUD indicators are not ported. `AnchorAuraScoring` is a Jilaton Java implementation of the observed scoring rule. Anubis is GPL-3.0; supplied JAR SHA-256: `c5259f9ffee4bbe2511972f7941ab6fc2dcda691dc0d5ab18a558f3f8f4285de`.

`WTapModule` adapts Anubis's `WTapRecodeModule` attack lifecycle by recording a qualifying sprint hit before the client attack and applying the sprint release only after the attack call completes. W-Tap and S-Tap movement shaping follows the semantics of Anubis's `InputControl.releaseForward`: clear forward for the configured tap period, and also set backward for S-Tap. The movement input event, Minecraft mixin/accessor, timing, and settings are Jilaton Java implementations. The installed LiquidBounce JAR's `ModuleSuperKnockback` and nested WTap/SprintTap classes were statically inspected with `javap`; no LiquidBounce implementation is represented as copied into this module. Anubis is GPL-3.0; supplied JAR SHA-256: `c5259f9ffee4bbe2511972f7941ab6fc2dcda691dc0d5ab18a558f3f8f4285de`.

`CriticalsModule` adapts the Jump mode's wait-for-falling-critical decision from the compiled `ModuleCriticals` / `CriticalsJump` classes in the installed LiquidBounce 0.37.0 JAR. Jilaton's attack queue, callback cancellation/replay, environmental checks, and settings are Java implementations. Packet, NoGround, Blink, and Timer modes are not included: they need packet-order and timer-control infrastructure that this module system does not currently provide. LiquidBounce is GPL-3.0-or-later; inspected JAR SHA-256: `6bbf432cc5b829963b671c8b948e33e6cdb7a66d14f3a2f8507cad4f3f94f898`.

`AutoArmorModule` adapts the full-equipped-kit comparison approach from LiquidBounce's compiled `ModuleAutoArmor`, `ArmorEvaluation`, `ArmorComparator`, and `ArmorPiece` classes. Its estimated six-point damage model uses the observed armor/toughness formula and the compiled enchantment weights; Jilaton adds its own durability threshold, Binding Curse filter, timing controls, and inventory transaction lifecycle. LiquidBounce is GPL-3.0-or-later; inspected JAR SHA-256: `6bbf432cc5b829963b671c8b948e33e6cdb7a66d14f3a2f8507cad4f3f94f898`.

`TargetStrafeModule` adapts the Input-mode target tracking and orbit planning from LiquidBounce's compiled `ModuleTargetStrafe` (2.95 block default orbit range, 4.0 follow range, direction selection, and KillAura target dependency). Jilaton's radial correction, yaw-relative input projection, lifecycle, and settings are Java implementations using its movement-input event. The Motion mode, adaptive collision planner, and rendering marker are not ported: Jilaton does not yet have the required cancellable player-move event, adaptive block-edge planner, or TargetStrafe visual system. LiquidBounce is GPL-3.0-or-later; inspected JAR SHA-256: `6bbf432cc5b829963b671c8b948e33e6cdb7a66d14f3a2f8507cad4f3f94f898`.

`AutoClickerModule` is informed by static inspection of LiquidBounce's compiled `ModuleAutoClicker`, `Clicker`, and click-pattern classes. Jilaton implements its own Java tick/crosshair attack path, configurable minimum/maximum CPS, optional attack-key, vanilla attack-cooldown and item-use guards, and a bounded Gaussian CPS sampler. The sampler is a Jilaton implementation inspired by the reference's named normal-distribution pattern; it is not a byte-for-byte port of `NormalDistributionPattern`. LiquidBounce's separate right-click `UseButton`, specialized item/objective/critical/sprint behavior, and other click patterns are not included. The installed LiquidBounce JAR is GPL-3.0-or-later; inspected SHA-256: `6bbf432cc5b829963b671c8b948e33e6cdb7a66d14f3a2f8507cad4f3f94f898`.

`HitboxModule` adapts LiquidBounce's compiled `ModuleHitbox` behavior: its `Size` setting is applied as the eligible entity's pick-radius margin, with the observed 0.1 default and 0–1 range. Jilaton applies the setting at `Entity.getPickRadius()` return and retains its own player/friend/team/anti-bot checks. Physical collision bounds and the reference's debug/component rendering settings are not changed. LiquidBounce is GPL-3.0-or-later; inspected `ModuleHitbox` SHA-256 is covered by the full installed JAR SHA-256 `6bbf432cc5b829963b671c8b948e33e6cdb7a66d14f3a2f8507cad4f3f94f898`.

`ReachModule` adapts the compiled LiquidBounce `ModuleReach` / `RangeValueGroup` path. The observed entity bonus defaults to 1.0 with a 0–5 range; block-range increase defaults to 0.5 with a 0–64 range. Jilaton modifies only the local player's entity/block interaction-range accessors and adjusts the `AttackRange` component's survival/creative maxima while preserving the other component fields. The separate through-wall range value is not carried into Jilaton because its targeting path has no independent through-wall range mode; the module does not bypass server validation. LiquidBounce is GPL-3.0-or-later; inspected JAR SHA-256: `6bbf432cc5b829963b671c8b948e33e6cdb7a66d14f3a2f8507cad4f3f94f898`.
